## 3. The `ISSetupStream` Container Format

The overlay container begins at file offset `0x144E00` with the 14-byte signature `ISSetupStream\0`.

### Archive Header Structure (46 bytes / 0x2E)
| Field | Type | Offset | Description |
| :--- | :--- | :--- | :--- |
| `SIG` | `char[14]` | 0x00 | Signature string: `"ISSetupStream\0"` |
| `num_files` | `uint16_t` | 0x0E | Number of embedded files (`4`) |
| `type` | `uint32_t` | 0x10 | Container version type (`4`) |
| `x4` | `uint8_t[8]` | 0x14 | Reserved / timestamp bytes |
| `x5` | `uint16_t` | 0x1C | Flags |
| `x6` | `uint8_t[16]` | 0x1E | Reserved padding |

### File Header Structure (24 bytes / 0x18 per entry)
Followed by an additional 24-byte padding block when `type == 4`:
| Field | Type | Description |
| :--- | :--- | :--- |
| `filename_len` | `uint32_t` | Length of filename in bytes (UTF-16LE encoded) |
| `encoded_flags` | `uint32_t` | Encryption flags (`0x06`: bit 2 = encoded, bit 4 = 1024-byte block decode) |
| `x3` | `uint16_t` | Unknown flags |
| `file_len` | `uint32_t` | Length of encoded payload data in bytes |
| `x5` | `uint8_t[8]` | Checksum / file dates |
| `is_unicode_launcher` | `uint16_t` | Compression flag (`1` = zlib / Deflate compressed) |

### Decryption & Decompression Algorithm
1. **Key Generation**:
   The key is generated by XORing the UTF-8 filename bytes with a fixed 4-byte magic sequence:
   $$\text{key}[i] = \text{filename\_utf8}[i] \oplus [0\text{x}13, 0\text{x}35, 0\text{x}86, 0\text{x}07][i \pmod 4]$$

2. **Byte Transformation**:
   For each byte in 1024-byte blocks:
   $$\text{swapped} = ((b \ll 4) \ \& \ 0\text{xF}0) \mid ((b \gg 4) \ \& \ 0\text{x}0\text{F})$$
   $$\text{decoded} = \sim(k \oplus \text{swapped}) \ \& \ 0\text{xFF}$$
   where $k = \text{key}[(i \pmod{1024}) \pmod{\text{len(key)}}]$.

3. **Inflation**:
   The decoded stream is decompressed via standard `zlib.decompress(data)`.
